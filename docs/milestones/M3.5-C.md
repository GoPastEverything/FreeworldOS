# M3.5-C — Tasks and Deterministic Context Switching

Status: C1-C2e are frozen; C2e merged on `main` at `feace76c`; C2f replaces only the LAPIC timer entry with a full hand-written interrupt frame and returns to the same task with IRETQ.

Frozen prerequisite: M3.5-B is merged on `main` at `269874c`.

M3.5-C is deliberately split so stack ownership and overflow detection are proven before any saved CPU context or switch path exists.

## C1 — task object and owned kernel stack

This first commit adds only the task object and its stack.

A task is a native kernel object with:

- a monotonically assigned task ID;
- state `Created`;
- one kernel stack it owns.

There is no saved register frame, runnable queue, scheduler, yield primitive, context switch, priority, SMP scheduling, or timer-driven preemption in C1.

### Stack layout

Each task receives four mapped 4 KiB RW/NX stack pages (16 KiB total) from the existing physical-frame allocator/recycler.

The virtual layout is:

~~~text
low address
+--------------------+
| guard page         |  reserved; leaf PTE not present
+--------------------+  <- stack_bottom
| stack page 0       |
| stack page 1       |
| stack page 2       |
| stack page 3       |
+--------------------+  <- stack_top
high address
~~~

The guard page owns no physical frame. Only the four stack pages are backed. In C2b the guard address is also registered in the architecture-neutral virtual-page reservation table, so generic `map_page()` calls fail with `VirtualPageReserved` while the task owns the stack slot.

C1 originally placed task-stack virtual slots in the lower half. Before C2 saves any stack pointer, the task-stack region moves to the kernel higher half at `0xffff_a000_0000_0000`, alongside the existing higher-half heap/device mappings. Slots remain monotonic for now; virtual-slot reuse is deferred.

### Ownership and reclamation

The `TaskObject` owns its `KernelStack`.

Construction:

1. reserves one virtual stack slot;
2. obtains each physical stack page through `memory::allocate_frame()`;
3. maps the page RW/NX through the existing FreeWorld mapper;
4. never maps the guard page.

Destruction:

1. unmaps every owned stack page;
2. verifies the unmapped physical frame is the frame the stack recorded;
3. returns each frame through `memory::free_frame()`.

Thus stack backing participates in the M3.5-A recycler rather than using a static stack array.

## C1 CI proof

The cumulative self-test creates a task object and proves:

- the object can be retrieved as a task;
- its ID is nonzero;
- its state is `Created`;
- the stack layout is guard + four pages;
- the bottom and top of the mapped stack are writable;
- closing the object returns exactly four owned stack frames.

The named result is:

~~~text
FreeWorldOS: SELFTEST PASS name=m3.5c.task_stack
~~~

A separate deliberate-fault image creates a task and stores into the guard page below its stack.

CI requires the existing M3.5-B fatal page-fault path to report:

~~~text
FreeWorldOS: FATAL
FreeWorldOS: EXCEPTION: #PF page fault
fault=0xffffa00000000000
~~~

The guard proof adds no special exception handler.

## C2 — higher-half layout, then voluntary switch

C1 is merged. Before any saved context bakes in a stack address, C2 first moves task stacks to the kernel higher half at `0xffff_a000_0000_0000`.

### C2b — ownership gate

Before the first runnable task is allowed, C2b enforces three execution-time invariants:

- the handle table refuses the final handle close while a task is `Runnable` or `Running`, or while saved stack state is owned; non-final handles may still close because another handle retains the object;
- a live guard-page address is reserved independently of its not-present PTE, and generic `map_page()` refuses that address until task destruction releases the reservation;
- each task exposes an initial stack pointer at `stack_top - 8`, so `RSP % 16 == 8` at direct System V function entry, equivalent to the return-address-sized slot present after a normal call.

The ownership self-test proves that a stopped task with no saved stack state can close, reclaim its stack, release its guard reservation, and allow that virtual page to be mapped again.

`ObjectBusy` on final close is a bootstrap guard. Starting in C2c, the scheduler owns a strong reference to every Runnable/Running/saved task, so stack lifetime never depends on handle-close behavior; `TaskObject::Drop`'s assertion remains the tripwire. This also covers future process-table teardown paths that remove handles without calling the polite close operation.

Monotonic stack-slot exhaustion remains acceptable during bootstrap, but stack-slot reuse must exist before M5/user workloads create and destroy tasks repeatedly.

The virtual-page reservation table also remains bootstrap-scale: address 0 is rejected explicitly, the current check-then-claim path is not SMP-safe for two CPUs racing on the same address, and the 1024-entry linear scan can be replaced when mapping frequency and SMP justify it.

### C2c — first voluntary switch

C2c adds one x86_64 saved-register-frame format:

~~~text
low address / saved RSP
r15
r14
r13
r12
rbp
rbx
return RIP
synthetic return slot (0)
high address
~~~

The switch primitive is a normal SysV call boundary. It pushes the six callee-saved general registers, stores the current RSP, loads the next task's saved RSP, restores those registers, and returns through the saved RIP. Caller-saved registers and flags are not scheduler state because the compiler already treats them as clobbered across a normal call.

The scheduler owns the strong references for task A and task B. The CI proof deliberately creates temporary handles and closes them before either task becomes Runnable, proving that live stack ownership comes from the scheduler rather than the handle table.

The first execution proof is limited to:

- task A enters on its own higher-half task stack and prints a serial line;
- task A performs one explicit cooperative yield;
- the switch saves A's register frame/RSP;
- task B restores its prepared frame, enters on its own task stack and prints a serial line;
- task B verifies A is Runnable, A has saved stack state inside A's stack, B is Running, and the scheduler still owns the sole strong reference to both tasks;
- task B prints the pass line and halts.

C2c still has:

- no priority policy;
- no run-queue selection beyond the fixed A -> B proof;
- no SMP scheduling;
- no timer-driven preemption;
- no serial lock.

Timer interrupts may still occur through the existing M2 handler, but that handler does not inspect the scheduler or cause a switch. Timer-driven preemption remains gated until this voluntary A -> B proof has been reviewed and frozen.

## Deferred M3.5-B rules remain binding

The panic/fatal path still does not take a serial lock. Before normal serial output ever gains a lock, panic and NMI output must remain on a raw fixed-buffer path.

A fatal exception that begins on an IST stack cannot recover an interrupted task's frame-pointer chain in C1. Recovery through saved task state belongs after task stacks/context exist and must be reviewed separately.


### C2d — interrupt-safe voluntary round trip

C2c proved the mechanics of A -> B. C2d closes the maskable-interrupt window around scheduler state publication and proves that a previously saved task can resume.

The cooperative-switch interrupt policy is intentionally narrower than a future preemptive trap frame:

- a voluntary yield is legal only when IF is already enabled;
- the scheduler executes `CLI` before changing Running/Runnable state or publishing the next current task;
- IF remains clear while the outgoing task still contains a stale saved-RSP value and while the assembly switch writes the real one;
- after the incoming task's stack and callee-saved register frame are restored, the switch path executes `STI` immediately before returning on that task's stack;
- therefore cooperative tasks always resume with IF enabled;
- full RFLAGS are not stored in the C2d saved frame. Arithmetic flags are caller-clobbered across the yield call, and preemptive/trap resumption will define its own complete CPU frame later.

NMIs remain unmasked, but the current NMI/debug paths do not inspect or mutate scheduler state.

The C2d proof is:

~~~text
bootstrap
  |
  | IF on
  v
CLI -> publish A Running/current
  |
  | switch to A stack, STI
  v
A running
  |
  | voluntary yield
  v
CLI -> A Runnable/saved, B Running/current
  |
  | save real A RSP, restore B, STI
  v
B running
  |
  | voluntary yield
  v
CLI -> B Runnable/saved, A Running/current
  |
  | save real B RSP, restore A, STI
  v
A resumes after its original yield call
~~~

A verifies that B now owns valid saved stack state inside B's live higher-half stack and that IF is enabled after the return. CI also rejects `PANIC REENTRY` for both the original C2c image and the C2d round-trip image.

C2d still adds no run-queue selection, priority policy, SMP scheduling, timer-driven preemption, or serial lock. Timer preemption remains explicitly gated.


### C2e — IRQ-on-task-stack proof

C2e is the final cooperative-switch proof before a preemptive trap frame.

Two invariants are tightened:

- the incoming task's saved RSP is read and range-checked only after `CLI`, so the voluntary path already has the ordering needed when a timer can later make another task runnable;
- both task B and resumed task A snapshot `rt::time::now()`, execute `HLT` with IF enabled until the LAPIC timer tick advances, and then continue on the same task stack.

The timer handler still does not inspect scheduler state or switch tasks. A successful tick advance therefore proves that a real timer interrupt arrived while each task stack was active and returned cleanly to that task.

C2e remains non-preemptive. The next scheduler step must introduce a full preemptive/trap CPU frame, including RFLAGS, before the timer is permitted to select or switch tasks.


### C2f — timer-only full interrupt frame

C2f does not preempt or select another task. It changes only the LAPIC timer entry so the future preemptive path has a complete, explicit CPU frame to build on.

The timer IDT entry uses a hand-written assembly stub rather than Rust's `extern "x86-interrupt"` ABI. In 64-bit mode the processor aligns RSP before interrupt-frame construction and pushes five 8-byte values for this no-error-code timer gate:

~~~text
SS
RSP
RFLAGS
CS
RIP
~~~

The assembly entry then pushes all fifteen general-purpose registers. From low address / saved RSP the resulting fixed timer frame is:

~~~text
r15
r14
r13
r12
r11
r10
r9
r8
rbp
rdi
rsi
rdx
rcx
rbx
rax
RIP
CS
RFLAGS
RSP
SS
~~~

That is 20 qwords / 160 bytes. Five hardware qwords plus fifteen GPR qwords preserve 16-byte alignment before the assembly stub calls Rust. C2f CI records and checks that alignment.

This layout is timer-only. C2f deliberately does not unify exceptions that push error codes with exceptions/interrupts that do not.

Tasks now carry an explicit saved-context kind:

- `None`: running/created state has no resumable frame;
- `Voluntary`: resume through the cooperative `ret` path;
- `Interrupt`: resume through an interrupt `iretq` path.

The C2f timer proof temporarily publishes the live 160-byte timer frame into the running task as `Interrupt`, verifies the full frame and the hardware return RSP lie inside the owned higher-half stack, acknowledges the LAPIC, clears the temporary saved-context state, restores all GPRs and returns through `iretq` to the same task. No timer-driven switch exists.

#### EOI ordering

`apic::timer_interrupt()` performs tick accounting and LAPIC EOI. Any future scheduler decision or task handoff from timer context must happen only after that EOI. A task switch must never defer controller completion until the interrupted task runs again.

#### Interrupt-depth ownership

The interrupt nesting depth tracks active handler execution on the CPU; it is not task state and is not stored in a saved interrupt frame. Before a future timer handler hands execution to another task, the interrupt scope must be dropped after EOI so `in_interrupt()` is false. Restoring a saved interrupt frame through `iretq` does not increment that counter.

#### C2f proof

The dedicated image proves:

- the timer frame is exactly 160 bytes and 16-byte aligned at the Rust call boundary;
- saved context is observed as `Interrupt` while the handler owns the frame;
- the frame and hardware return RSP are inside the running task's stack;
- the interrupted RFLAGS image had IF set;
- LAPIC EOI occurs before the documented future scheduling point;
- interrupt depth is clear after return;
- fixed values placed in RBX, RBP and R12-R15 survive the timer interrupt;
- `iretq` returns to the same task;
- the timer still does not select or switch tasks.

The next step may design restoration/dispatch by frame kind, but timer-driven task selection remains gated until the interrupt-frame proof is reviewed and frozen.
