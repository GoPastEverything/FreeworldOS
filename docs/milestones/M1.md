# M1 — CPU Exception and Memory Foundation

Status: implementation complete on `m1-foundation`; BIOS boot paths validated by GitHub Actions/QEMU before merge.

## Scope

M1 establishes the first FreeWorld-owned CPU and memory-management foundation on x86_64.

### CPU tables and exceptions

- FreeWorld GDT replaces reliance on the bootloader's descriptor table after entry.
- A TSS is installed with a dedicated five-page, 16-byte-aligned double-fault IST stack.
- The FreeWorld IDT covers every architecturally defined x86_64 CPU exception exposed by the `x86_64` crate.
- Architecturally reserved vectors are intentionally left absent.
- Page faults report CR2 and the page-fault error flags.
- Fatal exceptions emit a fixed `FreeWorldOS: FATAL` marker, log their identity/frame, and halt.
- Breakpoint is recoverable and used as the M1 CI exception proof.
- Interrupts remain disabled during M1; APIC/timer interrupt enablement belongs to M2.

### Boot memory discovery

The x86_64 bootstrap requests a dynamic physical-memory mapping from the rust-osdev bootloader, then records/logs:

- kernel physical range
- kernel virtual image base
- ramdisk physical range when one exists
- physical-memory mapping offset
- every region marked usable by the firmware/bootloader map
- total usable memory
- active CR3 frame

A firmware/bootloader `Usable` label is necessary but not sufficient for frame allocation. The M1 allocator additionally excludes:

- all physical addresses below 1 MiB, preserving low memory for firmware/legacy needs and future AP startup work;
- the loaded kernel physical range;
- the ramdisk physical range when present.

### Physical frame allocator

M1 uses a monotonic bootstrap frame allocator over usable memory-map regions.

Properties:

- returns unique 4 KiB frames
- skips all non-usable regions
- never allocates below 1 MiB
- explicitly excludes the loaded kernel image
- explicitly excludes the ramdisk when present
- contains no heap dependency
- is hidden behind the FreeWorld `memory::allocate_frame()` interface
- deliberately does not recycle frames yet

This allocator is sufficient for bootstrap page-table construction and is intended to be replaced by a reclaiming allocator in a later memory-management milestone.

`unmap_page()` returns the frame that used to be mapped, but M1 has no frame deallocator. That frame remains caller-owned and must not be treated as automatically returned to a reusable free pool.

### Virtual memory

The x86_64 architecture layer takes exclusive mutation responsibility for the active CR3 page-table hierarchy through an `OffsetPageTable`.

The architecture-neutral FreeWorld memory interface exposes:

- `PhysFrame`
- `PagePermissions`
- `allocate_frame()`
- `map_page()`
- `unmap_page()`

x86_64-specific CR3, page-table flags, physical-offset mapping, and NXE handling stay under `kernel/src/arch/x86_64/`.

NX is enabled during memory initialization.

The generic permission model refuses writable + executable permissions for mappings FreeWorld creates through this API. This is not yet a global W^X guarantee: the bootloader-provided physical-memory mapping remains a writable alias of RAM, including memory backing kernel code. That bootstrap mapping must be hardened before untrusted userspace exists; the current target is no later than M5, with kernel code made read-only and non-code physical aliases non-executable where practical.

## CI proof

CI builds two distinct BIOS images:

1. the default kernel with no M1 self-test feature;
2. a feature-gated M1 self-test kernel.

The default BIOS image is booted under QEMU and must reach the M1/bootstrap completion markers with no panic, fatal marker, or exception output. This proves the feature gate does not mask a broken default kernel.

The self-test BIOS image proves:

1. the kernel boots after installing its own GDT/TSS/IDT;
2. physical memory is discovered and the active page tables are accessible;
3. a real usable physical frame is allocated from the hardened allocator;
4. that frame is mapped RW + NX at a test virtual address;
5. a volatile write/read through that mapping succeeds;
6. the page is unmapped and returns the same physical frame;
7. W+X permission creation is rejected;
8. `INT3` reaches the FreeWorld breakpoint handler;
9. execution returns from the breakpoint handler;
10. no exception other than the expected `#BP` appears;
11. no `FreeWorldOS: FATAL` or `KERNEL PANIC` marker appears;
12. the kernel reaches `FreeWorldOS: M1 foundation online` and the bootstrap completion marker.

Validated serial markers include:

~~~text
arch: FreeWorld GDT/TSS/IDT online
memory: active CR3=... page_size=4096 bytes NX=on
memory: allocator floor=0x100000 kernel/ramdisk excluded
FreeWorldOS: M1 memory self-test: passed
FreeWorldOS: M1 exception self-test: trigger #BP
FreeWorldOS: EXCEPTION: #BP breakpoint
FreeWorldOS: M1 exception self-test: resumed
FreeWorldOS: M1 foundation online
FreeWorldOS: bootstrap initialization complete
~~~

The build system generates both BIOS and UEFI disk images, but M1 CI currently boot-tests BIOS only. UEFI boot verification remains a follow-up and is not claimed as M1 CI proof.

## Follow-ups

Before or during M2:

- add separate fault-injection boots for a known-address `#PF` and a stack-overflow `#DF` so the fatal path and dedicated double-fault IST are exercised directly;
- give NMI and machine-check dedicated IST stacks before external interrupts are enabled;
- add UEFI QEMU boot coverage;
- preserve the low-memory reservation needed for AP startup when SMP work begins.

Before untrusted native userspace (no later than M5):

- harden the bootstrap physical-memory mapping so it cannot remain a universal writable alias of kernel code/RAM;
- make kernel text read-only and enforce non-executable permissions on data/physical aliases where practical.

## Deferred to M2+

M1 intentionally does not implement:

- APIC timer setup
- external hardware interrupt routing
- scheduler preemption
- SMP
- reclaiming frame allocation
- a heap
- userspace/ring 3
- FreeWorld native syscalls

Those belong to later milestones.
