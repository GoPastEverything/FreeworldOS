# M5-AA — Task-owned syscall entry candidate

Adds a distinct `__freeworld_m5aa_syscall_entry` for the single user task. The `UserSyscallTask` owns a guarded four-page kernel stack and a boxed `TaskSyscallContext` with a stable kernel-half address. The CPU's IA32_KERNEL_GS_BASE is temporarily set to that task context for the controlled run. `SYSCALL` does not switch RSP, so the entry executes `SWAPGS`, saves the user RSP via GS, and immediately switches to the task kernel stack **before pushing registers or calling Rust**. No M5-O global return slots are read or updated on the new syscall path.

The return restores the saved RCX and R11 from task-owned memory, repeats M5-X's 48-bit canonicality check before SYSRET, restores user RSP, executes SWAPGS and SYSRETQ. Noncanonical values use the controlled ring-3 IRETQ abort path (not signal delivery). The acceptance test verifies the entry RSP equals the private top, the Rust handler ran inside the private stack, the process CR3 and return data are correct, the old global `seen` slot remains disarmed, the bootstrap TSS RSP0 was distinct and restored, STAR/LSTAR/SFMASK/EFER and GS MSRs were restored, and 10 owned frames were returned.

**Scope limits:** M5-O through M5-U continue exercising the legacy global-based entry for regression; they are not yet migrated. M5-AA tests the new task-owned path and does not make user scheduling, inter-CPU or reentrancy, concurrent mapping changes, or process lifecycle claims. One user process; IF masked; CPU-local GS state is configured solely around the controlled test. This is the entry foundation, not yet a production process execution service.
