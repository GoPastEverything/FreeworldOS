# M3.5-A — Physical Frame Return and Reuse

Status: merged and frozen on `main` at merge commit `b656622`.

M3.5-A is the first prerequisite after frozen M3. It adds physical-frame return/reuse behind the existing memory interface and nothing else.

No task stacks, saved context, runnable queues, scheduler policy, or context switching belong to this milestone.

## Scope

M3.5-A adds:

- an intrusive physical-frame free stack;
- `free_frame()` as an explicit ownership-transfer operation;
- recycled-frame-first allocation;
- frame scrubbing across ownership boundaries;
- an always-on one-bit-per-frame allocation-state bitmap;
- allocator ownership/state validation;
- constant-time double-free detection in all builds;
- reuse statistics;
- a QEMU self-test proving actual frame return and reuse.

## Recycler structure

Returned 4 KiB frames form a LIFO stack.

The frame itself stores the next physical frame address in its first machine word while the frame is allocator-owned:

~~~text
recycled_head
     │
     ▼
+-----------------------+
| next physical address |
|                       |
| allocator-owned page  |
|                       |
+-----------------------+
     │
     ▼
 next free frame
~~~

A zero next address terminates the stack. Frame zero is never allocatable because M1 permanently excludes physical memory below 1 MiB.

This free-stack design has no fixed metadata capacity and does not allocate heap memory.

Normal push and pop are O(1).

## Allocation-state bitmap

FreeWorld also reserves a compact physical-frame state bitmap at memory-manager startup, before normal frame allocation begins.

Each 4 KiB physical frame has one bit:

~~~text
0 = not currently allocated to an owner
1 = currently allocated
~~~

For 4 KiB frames, this costs **32 KiB per GiB of tracked physical memory**.

The bitmap storage itself is reserved from the same monotonic usable-memory source at startup, zeroed, and its own backing frames are permanently marked allocated/internal so they cannot be returned to the recycler.

If the startup reservation must advance past otherwise-usable frames to obtain its contiguous metadata run, those already-crossed frames are also marked bootstrap-consumed/internal. That prevents a clear state bit below the monotonic cursor from being mistaken for a legitimately recyclable frame.

Every successful allocation must transition its frame bit from 0 to 1. Every successful `free_frame()` must observe 1 and transition it to 0 before the frame becomes reusable.

This makes double-free detection and current ownership-state checks constant-time in debug and release builds.

## Allocation order

`allocate_frame()` first checks the recycler.

If a recycled frame is available:

1. remove the head;
2. recover the next link;
3. decrement the available count;
4. scrub the whole frame;
5. return it to the new owner.

Only when the recycler is empty does allocation continue from the original M1 monotonic firmware-memory walk.

Page-table allocations use the same allocator, so recycled frames may also satisfy later page-table frame requests.

## Returning a frame

`free_frame(frame)` is an unsafe ownership transfer.

The caller must prove that:

- it owns the frame exclusively;
- no owner-visible virtual mapping still names it;
- no raw pointer or kernel object still references it;
- no DMA mapping or device can still access it;
- the allocator's own privileged physical direct-map alias is the only allowed mapping and is used solely for recycler metadata/scrubbing;
- the caller will not touch the frame after a successful return.

The allocator validates that the physical address:

- is 4 KiB aligned;
- is at or above the M1 1 MiB floor;
- belongs to a bootloader region marked Usable;
- does not overlap the kernel or ramdisk reservations;
- was previously reached by the monotonic allocator rather than being a future frame;
- is not one of the allocator's own bitmap metadata frames;
- is currently marked allocated in the frame-state bitmap.

The last check is the always-on double-free guard.

The allocator then:

1. scrubs the entire frame;
2. stores the previous recycled-head address in the first word;
3. clears the frame's allocated bit;
4. makes the returned frame the new stack head.

## Why `unmap_page()` does not automatically free

Unmapping and physical ownership are separate operations.

`unmap_page()` removes one owner-visible virtual mapping and returns the physical frame to its caller. It cannot prove that some other owner-visible mapping, pointer, DMA operation, or device does not still reference that frame. The allocator's privileged physical direct-map alias is not ownership granted to the caller.

Therefore:

~~~text
unmap_page()
    ↓
caller owns PhysFrame
    ↓
caller proves all aliases are gone
    ↓
unsafe free_frame()
    ↓
allocator owns frame
~~~

M3.5-C task-stack teardown must obey the same ownership sequence.

## Scrubbing

A returned frame is zeroed before it joins the recycler.

A recycled frame is zeroed again after its intrusive next link is read and before it is returned to a new owner.

This prevents:

- stale task/object data from crossing ownership boundaries;
- recycler linkage metadata from becoming visible to the next owner.

The second scrub also makes the reuse proof directly observable in CI.

## Duplicate-return and corrupted-link discipline

The ownership contract makes returning an already-free frame a kernel bug.

The always-on allocation-state bitmap catches that condition in O(1) in every build. There is no free-list walk on `free_frame()`.

When a recycled frame is popped, the recycler also asserts that:

- the head is marked free;
- the stored next link names an allocator-managed frame;
- the next frame is marked free;
- neither head nor next points at allocator metadata.

A corrupted free-list link that points at a frame still owned elsewhere therefore fails before that frame can be handed to a second owner.

## Direct-map dependency

The current x86_64 implementation stores/reads the intrusive link through the bootstrap physical-memory direct map supplied by the bootloader.

This is an implementation dependency, not a FreeWorld memory-model requirement.

When the bootstrap direct map is hardened/replaced before untrusted userspace, the kernel must retain an equivalent **writable, no-execute, supervisor-only** view for recycler links, frame scrubbing, and the allocation-state bitmap, or move that metadata behind another privileged mapping. User mode must never inherit this writable physical alias.

## SMP prerequisite

M3.5-A is bootstrap-CPU-only.

Before any SMP code may call `free_frame()`, FreeWorld needs cross-CPU TLB shootdown/acknowledgement. Clearing a mapping and invalidating it only on the local CPU is insufficient: another CPU could retain a stale translation and write into a frame after that frame has been reassigned.

The required SMP ordering is:

~~~text
remove owner-visible mappings
    ↓
broadcast TLB invalidation
    ↓
wait for every relevant CPU to acknowledge
    ↓
free_frame()
    ↓
frame may be reused
~~~

This requirement belongs on the SMP prerequisite list alongside per-CPU interrupt state and bootstrap-only LINT1/NMI policy.

## Statistics

The architecture-neutral memory interface exposes frame-reuse statistics:

- `available`: frames currently on the recycler;
- `returned_total`: successful frame returns;
- `reused_total`: allocations satisfied from the recycler.

These are diagnostic counters, not resource-accounting authority.

## CI proof

The M3.5-A self-test runs before maskable interrupts are enabled.

It proves:

1. a low/non-allocator frame is rejected;
2. a fresh frame can be allocated and its state bit is 1;
3. the frame can be mapped RW and written;
4. unmapping returns that exact frame;
5. returning it clears the state bit to 0 and increases recycler availability;
6. the very next `allocate_frame()` returns the same physical frame and sets its bit back to 1;
7. recycler availability falls again;
8. `reused_total` increases;
9. remapping the recycled frame observes zeroed contents;
10. the frame can be unmapped and returned again, leaving its state bit clear for later bootstrap reuse.

CI requires a marker of the form:

~~~text
FreeWorldOS: M3.5-A frame reuse self-test: passed bitmap_state=ok available=<nonzero> returned_total=<nonzero> reused_total=<nonzero>
~~~

All M0-M3 cumulative proofs remain required in the same self-test boot.

## Milestone boundary

M3.5-A proves only physical-frame return/reuse.

The next milestone is **M3.5-B**, the debugging foundation:

- structured kernel event ring;
- panic/fatal backtrace;
- QEMU/GDB host tooling;
- named self-test harness.

Only after M3.5-B is complete does **M3.5-C** begin task stacks, saved context, runnable state, and scheduler/context switching.
